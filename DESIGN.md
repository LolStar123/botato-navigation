# Botato route lab

## Audience and job

A visitor explores how navigation responds to changing terrain and encounters. The primary action is interacting with the world. Route diagnostics remain secondary.

## Design references and signature

The original `reference/Pathfinder.cs` and `reference/PathSmoother.cs` provide the stages: wall clearance, eight-direction search and collision-checked smoothing. The authored terrain and red-capped meowl supply the visible identity. They are code-native sandbox artwork, not assets from a game process.

A restrained 980 px frame puts the map beside its tools, with an inset terrain border and an external status line. The canvas preserves its 960 ? 600 aspect ratio, including on phones; the page never clips controls to preserve that ratio. Metadata and search settings sit below the map. Terrain, route, destination and enemies have distinct shapes and colours.

## Interaction states

Destination, rock and erase tools have pressed states. Pointer capture keeps a drag coherent; cancellation releases it. The keyboard can move the destination and draw/erase there, while Space controls pause. Rocks are refused near the traveller. Blocked routes stop movement and explain how to reopen a passage. Reset restores terrain and enemies; it keeps the user's pause state.

The encounter loop shows health, interruption, a cleared count and resumed travel. Reduced motion holds decorative bobbing/pulsing at a static phase; collision-checked movement and combat outcomes continue. Search timings are real current-browser readings, not claims about production speed.

## Shared implementation rules

Fonts come from the operating system; no font files or external requests are bundled. Layout starts from the working product, with no marketing cards, decorative gradients, scroll reveals or invented statistics. Code-native artwork stays editable. Controls use at least 44 px hit areas where practical and a visible two-pixel keyboard outline. Reduced motion disables decorative animation; essential state changes still happen.

Local acceptance: 1280 ? 1000 desktop and 390 ? 844 mobile, no horizontal page overflow, main flow and export, keyboard focus, unavailable/error states, and no uncaught page errors. README previews and ignored `output/qa/` screenshots are generated by the actual browser audits. Screenshots were visually inspected; the review is a solo craft check, not user testing.
